# Looper

Лёгкий псевдо-многопоточный событийно-ориентированный фреймворк для Arduino

Looper решает проблему организации кода в проектах Arduino, предоставляя диспетчер задач, который управляет несколькими независимыми контекстами выполнения без накладных расходов полноценной RTOS. Он позволяет использовать событийное программирование, периодическое выполнение задач и асинхронное ожидание в однопоточной среде.

## ✨ Особенности

- **Диспетчер задач** - Центральный менеджер задач, который выполняет все зарегистрированные задачи
- **Тикеры** (`LoopTicker`) - Задачи, которые выполняются непрерывно на каждой итерации цикла
- **Таймеры** (`LoopTimer`) - Задачи, которые выполняются через указанные интервалы времени
- **Потоки** (`LoopThread`) - Кооперативные потоки с асинхронными задержками и ожиданием, основанные на [машине Даффа](https://en.wikipedia.org/wiki/Duff%27s_device)
- **Обработчики событий** (`LoopListener`) - Задачи, которые реагируют на события
- **Статическое и динамическое создание задач** - Создание задач во время компиляции или выполнения
- **Система событий** - Отправка событий и данных между задачами
- **ООП API** - Создание собственных классов задач путём наследования базовых классов
- **Без зависимостей** - Работает без внешних библиотек
- **Лёгкий вес** - Ядро занимает 450 байт флеш-памяти и 5 байт оперативной памяти (AVR, при отключённых ID и событиях)
- **Независим от Arduino** - Может быть портирован на другие платформы путём замены двух платформенных функций

## 🚀 Быстрый старт

### Установка

#### Arduino IDE / Arduino IDE v2
1. Откройте менеджер библиотек (Сервис → Управление библиотеками)
2. Найдите "Looper"
3. Нажмите Установить

#### PlatformIO
Добавьте в ваш `platformio.ini`:
```ini
lib_deps =
    gyverlibs/Looper
```

#### Ручная установка
1. Скачайте библиотеку в виде ZIP-файла
2. В Arduino IDE: Скетч → Подключить библиотеку → Добавить .ZIP библиотеку...
3. Выберите скачанный ZIP-файл

Альтернативно, распакуйте ZIP и скопируйте папку `Looper-main` в директорию библиотек Arduino:
- Windows: `Documents/Arduino/libraries/` или `C:\Program Files\Arduino\libraries\`
- macOS: `~/Documents/Arduino/libraries/`
- Linux: `~/Arduino/libraries/`

### Минимальный пример

```cpp
#include <Looper.h>

void setup() {
    Serial.begin(115200);
}

void loop() {
    LP.loop();  // Вызов диспетчера в главном цикле
}
```

### Создание задач

```cpp
#include <Looper.h>

// Создание тикера, который выполняется на каждой итерации цикла
LP_TICKER([]() {
    Serial.println("Tick!");
});

// Создание таймера, который выполняется каждые 500 мс
LP_TIMER(500, []() {
    Serial.println("Timer!");
});

void setup() {
    Serial.begin(115200);
}

void loop() {
    LP.loop();
}
```

## 🛠 Использование

### Типы задач

#### LoopTicker
Выполняется на каждой итерации цикла. Поддерживает состояния Setup, Loop, Exit и Event.

```cpp
LP_TICKER([]() {
    switch (LP.thisState()) {
        case tState::Setup:
            Serial.println("Инициализация...");
            break;
        case tState::Loop:
            // Основное выполнение
            break;
        case tState::Exit:
            Serial.println("Очистка...");
            break;
        case tState::Event:
            Serial.println("Получено событие!");
            break;
    }
});
```

#### LoopTimer
Выполняется через указанные интервалы времени. Автоматически обрабатывает тайминг.

```cpp
LP_TIMER(1000, []() {
    Serial.println("Выполняется каждую секунду");
});

// Таймер с включёнными состояниями
LP_TIMER(500, []() {
    if (LP.thisState() == tState::Setup) {
        Serial.println("Настройка таймера");
    } else if (LP.thisState() == tState::Loop) {
        Serial.println("Тик таймера");
    }
}, true, true);  // start=true, states=true
```

#### LoopThread
Кооперативные потоки с асинхронными задержками. Потоки могут отдавать управление и возобновлять выполнение позже.

```cpp
LP_THREAD({
    pinMode(LED_BUILTIN, OUTPUT);

    while (true) {
        digitalWrite(LED_BUILTIN, HIGH);
        LP_DELAY(500);  // Неблокирующая задержка
        digitalWrite(LED_BUILTIN, LOW);
        LP_DELAY(500);
    }
});
```

**Важно**: Используйте `static` переменные для данных, которые сохраняются между передачами управления потоком:

```cpp
LP_THREAD({
    static int i;  // Должно быть static!
    for (i = 0; i < 10; i++) {
        Serial.println(i);
        LP_DELAY(100);
    }
});
```

#### LoopListener
Реагирует на события, отправленные другими задачами или главной программой.

```cpp
LP_LISTENER_("my_listener", []() {
    Serial.println("Получено событие!");
    void* data = LP.eventData();
    LoopTask* source = LP.eventSource();
});

// Отправка события
LP.sendEvent("my_listener");  // Отправить немедленно
LP.pushEvent("my_listener");  // Поставить в очередь на следующую итерацию цикла
```

### ID задач

Задачи могут иметь ID для идентификации и нацеливания событий:

```cpp
// Использование строковых ID (хэшируются во время выполнения)
LP_TIMER_("sensor_timer", 1000, []() {
    // ...
});

// Использование строк, хэшируемых во время компиляции
LP_TIMER_(LPH("sensor_timer"), 1000, []() {
    // ...
});

// Использование числовых ID
LP_TIMER_(123, 1000, []() {
    // ...
});

// Использование enum (рекомендуется для больших проектов)
enum IDs : hash_t {
    sensor_timer = 1,
    display_ticker,
    wifi_listener
};

LP_TIMER_(IDs::sensor_timer, 1000, []() {
    // ...
});
```

### Доступ к задачам

```cpp
// Получить задачу по ID
LoopTask* task = LP.getTask("my_task");
// или используя operator[]
LoopTask* task = LP["my_task"];

// Включить/выключить задачу
task->disable();
task->enable();
task->toggle();

// Удалить задачу
LP.remove(task);
// или изнутри самой задачи
LP.removeThis();
```

### События

События позволяют задачам взаимодействовать:

```cpp
// Обработчик событий с ID
LP_LISTENER_("event_id", []() {
    if (LP.eventBroadcast()) {
        Serial.println("Широковещательное событие");
    } else {
        Serial.println("Направленное событие");
        Serial.println(LP.eventSource()->id());
    }
});

// Отправить событие немедленно
LP.sendEvent("event_id", (void*)"data");

// Поставить событие в очередь на следующую итерацию цикла
LP.pushEvent("event_id");

// Отправить всем обработчикам
LP.sendEvent(LP_BROADCAST);
```

### Динамические задачи

Задачи могут создаваться и удаляться во время выполнения:

```cpp
void setup() {
    // Создание динамической задачи
    new LoopTicker([]() {
        Serial.println("Динамический тикер");
        if (someCondition) {
            delete LP.thisTask();  // Удалить себя
        }
    });

    // Или использовать отложенное удаление с состоянием Exit
    new LoopTicker([]() {
        switch (LP.thisState()) {
            case tState::Loop:
                if (someCondition) {
                    LP.removeThis();  // Поставить в очередь на удаление
                }
                break;
            case tState::Exit:
                delete LP.thisTask();  // Очистка
                break;
        }
    });
}
```

### Собственные классы задач

Создавайте собственные классы путём наследования базовых типов задач:

```cpp
class LoopButton : public LoopTickerBase {
    LP_MAKE_CALLBACK(ClickCallback, void);

public:
    LoopButton(uint8_t pin, ClickCallback callback)
        : _pin(pin), _cb(callback) {
        pinMode(pin, INPUT_PULLUP);
    }

    void exec() override {
        if (!digitalRead(_pin)) {
            if (!_flag) {
                _flag = true;
                _cb();
            }
        } else {
            _flag = false;
        }
    }

private:
    uint8_t _pin;
    ClickCallback _cb;
    bool _flag = false;
};

// Использование
LoopButton btn(2, []() {
    Serial.println("Кнопка нажата!");
});
```

### SimpleTimer (автономный)

Используйте `SimpleTimer` без полной системы задач:

```cpp
LP_TICKER([]() {
    static SimpleTimer tmr(1000);

    if (tmr.interval()) {  // Возвращает true когда время истекло, автоматически перезапускает
        Serial.println("Прошла одна секунда");
    }

    // Или вручную
    if (tmr.ready()) {
        Serial.println("Время истекло");
        tmr.restart();
    }
});
```

## ⚙️ Конфигурация

Библиотеку можно настроить в `platform.h` или через флаги компиляции:

### Флаги компиляции (пример для PlatformIO)

```ini
build_flags =
    -D LOOPER_QUEUE_SIZE=0    ; Отключить очередь событий
    -D LOOPER_USE_EVENTS=0    ; Отключить функцию событий
    -D LOOPER_USE_ID=0        ; Отключить ID задач
```

### Доступные настройки

- `LOOPER_QUEUE_SIZE` - Размер очереди событий (по умолчанию: 3)
- `LOOPER_USE_EVENTS` - Включить/отключить события (по умолчанию: true)
- `LOOPER_USE_ID` - Включить/отключить ID задач (по умолчанию: true)

Отключение функций уменьшает использование памяти. Минимальная конфигурация (события и ID отключены) использует ~450 байт флеш-памяти и ~5 байт RAM на задачу.

## 🔧 Совместимость с платформами

Совместимо со всеми платформами Arduino (AVR, ESP8266, ESP32, ARM и т.д.).

Библиотеку можно портировать на платформы, отличные от Arduino, реализовав две функции в `platform.cpp`:
- `looper::millis()` - Возвращает миллисекунды с момента запуска
- `looper::yield()` - Отдаёт управление другим задачам

## 📊 Производительность

- Накладные расходы выполнения задачи: ~8 мкс на задачу (AVR @ 16MHz), что эквивалентно ~2 вызовам `digitalRead()`
- Память на задачу: ~7 байт (можно уменьшить, отключив ID и события)
- Нет накладных расходов на стек для потоков (используется машина Даффа вместо переключения стека)

## 📝 Ограничения потоков

Потоки используют лёгкую реализацию на основе машины Даффа, которая имеет некоторые ограничения:

1. **Нет локальных переменных между передачами управления** - Используйте `static` переменные для данных, которые сохраняются между вызовами `LP_DELAY()` или `LP_WAIT()`
2. **Нет вложенных switch** - Не используйте `switch` операторы, которые содержат управляющие макросы потоков (`LP_DELAY`, `LP_WAIT` и т.д.)
3. **Единый контекст выполнения** - Все потоки выполняются в одном стековом фрейме

Подпись относится к текущей версии проекта.
